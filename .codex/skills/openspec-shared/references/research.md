# External research

Research external behavior only when repository evidence is insufficient or the exact dependency, protocol, server, framework, or runtime version matters.

1. Inspect repository evidence and pinned versions first: manifests, lockfiles, vendored source, generated clients, compatibility declarations, tests, and existing behavior.
2. Prefer version-matched primary sources in this order as applicable: dependency source and tests, official reference documentation, specifications, release notes, and changelogs.
3. Record the exact version, access date, direct link or repository path, and the precise claim each source supports.
4. Separate sourced fact from inference. State conflicts, uncertainty, unsupported assumptions, and any version gap explicitly.
5. Return evidence only. Do not choose workflow state, edit artifacts, or create a research note unless the current action explicitly authorizes that output.

Do not research from memory when version specificity can affect correctness. Secondary sources may help discovery but do not replace the primary source that owns the behavior.
